# 摘要：04 — System Prompt 工程：静态与动态的边界

## 概述
分析 Claude Code 如何从静态和动态两部分构建系统提示，解释 `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 标记如何分隔可缓存与不可缓存的内容，以及注入未缓存内容的逃生舱口。

## 核心要点
- **静态/动态边界**：系统提示在 `SYSTEM_PROMPT_DYNAMIC_BOUNDARY` 处分割。标记之前的内容在多轮对话中保持稳定，可参与提示缓存；标记之后包含每会话的动态数据（工作目录、当前时间、工具列表）。
- **`DANGEROUS_uncachedSystemPromptSection`**：用于注入必须始终保持最新内容（如实时环境状态）的逃生舱口，不会污染静态前缀的缓存。
- **分层组装**：系统提示通过按定义顺序组合命名片段（`corePersonality`、`toolDescriptions`、`memoryInstructions` 等）构建，使各片段可独立测试和替换。
- **工具描述注入**：每个工具通过 `Tool.prompt` 贡献自己的提示片段；注册表在构建时将这些片段合并到系统提示中，使工具描述与工具逻辑共同存放。
- **会话级记忆化**：静态片段每会话计算一次并缓存；只有动态片段在每轮对话时重新生成，最小化冗余字符串操作。

## 可迁移的设计模式
1. **显式缓存边界标记**：在系统提示中放置一个哨兵字符串，精确记录可缓存前缀的结束位置；测试静态片段在多轮对话间永不改变。
2. **将提示组合为命名片段**：将系统提示构建为有序的、可独立维护的片段列表，而非一个单体字符串；这使得对单条指令的单元测试成为可能。
3. **将工具描述放在工具逻辑旁边**：让每个工具导出自己的提示文本，当工具变化时，其描述自动保持同步。
